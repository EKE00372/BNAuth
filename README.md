# BNAuth

BNAuth 是 Windows 戰網驗證器管理工具，以 Rust 與 egui／eframe 開發。可在本機管理驗證器、產生八位驗證碼，並將資料保存於程式所在目錄。

本說明適用於 **0.4.0**。本版加入「從 Email 恢復」和「複製到分組」，並更新分組移轉、保存與校時流程。更新內容見 [v0.4.0 版本說明](.github/release-notes/v0.4.0.md)。

## 功能

- 手動匯入40位十六進位密鑰，或74位 WinAuth2 明文 `secretdata`。
- 從密鑰或 Email 恢復時，可在保存前核對驗證器資料與目前的八位驗證碼。
- 產生每30秒更新的八位驗證碼，支援複製與離線產碼。
- 所有驗證器共用校時，成功結果保存於 `.bnauth`，重開後沿用。從密鑰恢復、從 Email 恢復或匯入單組備份保存成功後，缺少有效校時才自動校時一輪。也可按時鐘手動校時。
- 分組、名稱搜尋、名稱與備註編輯、拖曳排序、複製到分組、批次移組及刪除。
- 單筆匯出 WinAuth2 XML，包含可產碼資料及名稱、備註、序號、還原碼。
- 右鍵分頁可將該分組的驗證器匯出成單組備份。
- 匯入 `.bnauth` 分組檔，預覽後建立新分組，保留完整資料與組內順序。同名分組自動加上編號。
- 完整資料庫備份與還原，保留全部分組名稱、驗證器資料、分頁及組內排序。
- 使用可直接閱讀的 JSON 資料檔，同一份資料由單一 BNAuth 程序管理。
- 視窗置頂、拖動與調整大小；每次啟動使用固定尺寸及位置。

全庫最多 1,000 筆驗證器、20 個分組（含「預設」），每組最多 100 筆。全庫滿 1,000 筆時，「＋ 新增」、「複製到分組」和「匯入單組備份」會停用。

## 下載

下載頁：[GitHub Releases](https://github.com/EKE00372/BNAuth/releases)。

選擇版本，在 **Assets** 下載 `BNAuth.exe`，即可直接執行，不需解壓縮或安裝。若尚無可下載的版本，請依下方步驟自行編譯。

EXE 已包含字型與授權文字；完整授權可在程式「說明」視窗的授權文字上按右鍵複製。

## 開始使用

1. 將 `BNAuth.exe` 放在本機 NTFS 磁碟中可寫入的資料夾，開啟程式。
2. 首次使用時按「建立」，建立空的 `BNAuth.bnauth`。已有完整備份時，可按「從備份還原」。
3. 按右下「＋ 新增」→「從密鑰恢復」，填寫名稱，貼上 40 位密鑰或 74 位明文資料。備註、序號與還原碼可選填。74 位資料會自動帶入並鎖定序號。按「預覽匯入」。
4. 在同一視窗核對八位驗證碼，並從「匯入至」選擇分組。名稱和備註仍可修改。更換密鑰後，重新按「預覽匯入」。確認無誤後按「確認」保存。
5. 按驗證器右側的複製圖示取得驗證碼。需要手動校時時，按分頁列右側的時鐘。尚未校時時，產碼使用 Windows 時間。

### 從 Email 恢復

1. 按右下「＋ 新增」→「從 Email 恢復」。填寫仍綁著該驗證器的帳號 Email、序號、原先保存的 10 位還原碼及名稱，再從「恢復至」選擇分組。「將 Email 存為備註」可把 Email 帶入備註欄，備註也可自行填寫或清空。
2. 按「開始恢復」。欄位格式正確且全庫與目標分組有空位時，程式才會向 Battle.net 送出恢復請求。等待回覆及核對驗證碼時，Email、序號與還原碼會鎖定。
3. 取回密鑰後，在同一視窗核對八位驗證碼。此時仍可修改名稱、備註和目標分組。按「確認」，保存成功後才加入一筆新紀錄。

保存失敗時，可按「重試」沿用已取回的資料。必要時由程式先清理暫存檔。按「放棄」會丟掉這次待存資料並保留磁碟上的檔案。

### 相同密鑰的提醒

只有透過右下「＋ 新增」添加驗證器時，才會在預覽比對全庫的長密鑰。找到相同密鑰時，畫面會列出最多五筆既有紀錄的分組和名稱。核對後可照常新增或取消。

兩種恢復都在確認前把資料暫存在記憶體。按「取消」或操作視窗右上角的 `×` 會丟掉這次結果。若 Email 恢復已送出請求，程式會捨棄之後收到的回覆。

同組與跨組都可以保存相同密鑰。每筆使用獨立 ID，保存各自的完整資料，並各計一筆容量。

### 複製到分組

在驗證器右側按三點選單，選「複製到分組」，再選另一個分組。原項目保留，完整副本會追加至目標分組末尾。各組的項目可獨立編輯與刪除。

容量足夠時，目標組已有相同密鑰也可以複製或移入。分組管理中可新增、改名、排序及刪除空分組，按「套用」才保存。

### 匯出 WinAuth2 XML

1. 在驗證器右側按三點選單，選「匯出 WinAuth2 XML」。
2. 閱讀匯出說明後按「另存新檔」，選擇位置並保存。預設位置為 EXE 同目錄，預設檔名為 `驗證器名稱.xml`，存檔時可自行修改。同名檔案會先詢問是否取代。
3. 用 WinAuth2 開啟 XML。每個檔案包含一筆驗證器，缺少的序號與還原碼維持空白。

XML **以明文保存密鑰與還原資料**。名稱、備註、序號與保存的還原碼另存於 `bnauth:metadata` 擴充區。WinAuth2 會忽略此區，仍可讀取密鑰與實際序號並產碼。**用 WinAuth2 重新保存後，擴充區會丟失，請保留 BNAuth 原匯出檔。** WinAuth2 畫面顯示的還原碼由它自行推算，可能與 XML 保存的值不同。

生成 XML 時會取用目前有效的共用校時偏移。WinAuth2 會把零時差視為「尚未校時」，首次取碼時嘗試連線舊版服務。偏移為零或缺少有效校時時，BNAuth 在 XML 寫入 **1 毫秒的相容值**。資料庫的校時偏移維持原值。

相容驗證使用 WinAuth **2.0.8.185 對應官方原碼**重新編譯的讀寫組件。首輪已核對含序號／純密鑰 XML 的讀取、固定時間 RFC 6238 產碼、重新保存及再次讀取；首次取碼的自動連線另按零時差修正驗證，使用者持有的原始 EXE 仍須另行核對。

### 匯出分組

1. 在要匯出的分頁上按右鍵，選「匯出此分組」。空分組的匯出選項停用。
2. 核對分組名稱與驗證器總數，再按「另存新檔」。
3. 預設檔名為 `分組名稱-YYMMDD.bnauth`，內建「預設」分組為 `Default-YYMMDD.bnauth`。日期取自本機，存檔時可自行修改。選到同名檔案時會先詢問是否取代。

分組備份保存該組名稱、組內排序及全部驗證器的名稱、備註、密鑰、序號與還原碼。搜尋條件與目前選取不影響匯出範圍。

檔案是**明文 UTF-8 JSON**，使用 `scope=group`。請使用「匯入單組備份」讀取。

### 匯入分組

1. 先建立或開啟目前資料庫，在任一分頁上按右鍵，選「匯入單組備份」。已有 20 組（含「預設」）或 1,000 筆驗證器時，這個選項會變灰。
2. 按「選擇檔案」，選取先前匯出的單組 `.bnauth`。有驗證器且容量足夠才會顯示預覽。
3. 核對新分組名稱、總筆數、第一筆驗證器的名稱及八位碼。每次匯入都建立新分組。若已有 `PTR`，會使用 `PTR(2)`、`PTR(3)` 等第一個可用的名稱。
4. 按「匯入」。成功後切換到匯入的分組。保存失敗可按「重試」或「放棄」。

比對分組名稱時不分大小寫，保留首尾空格。匯入保留組內排序和完整的驗證器資料。相同密鑰的紀錄各自加入，目標資料庫已有同一個 ID 時會為匯入的項目分配新 ID。

### 備份完整資料庫

1. 在任一分頁上按右鍵，選「備份完整資料庫」。
2. 核對分組與驗證器總數，再按「另存新檔」。預設檔名為 `BNAuth-YYMMDD.bnauth`。

完整備份保留所有分組、分頁順序、組內排序及驗證器資料，包含空分組和「預設」。檔案為**明文 UTF-8 JSON**，使用 `scope=full`。三種匯出都在選定位置後取得資料與當下有效的校時。正在使用的 `BNAuth.bnauth` 不能被匯出覆蓋。

### 還原完整備份

1. 在任一分頁上按右鍵，選「還原完整備份」。首次使用也可從啟動畫面按「從備份還原」。
2. 按「選擇檔案」，選取完整 `.bnauth` 備份，核對備份的分組與驗證器筆數。
3. 已有資料庫時，勾選「我已知曉目前資料將被全部取代。」再按「還原」。沒有資料庫時，直接按「還原」建立主檔。

還原會以完整備份取代目前全部資料，保留來源的所有分組名稱、驗證器完整欄位、分頁與組內排序。來源檔案保持原樣；分組檔請使用「匯入單組備份」。

程式會安全替換 `BNAuth.bnauth`，核對成功才更新畫面。保存失敗可按「重試」或「放棄」。完整還原沿用備份的有效校時偏移。備份校時不可用時，可沿用目前有效的結果。分組匯入則沿用目前資料庫的共用校時。

### 資料保存

資料保存在 EXE 同目錄的 `BNAuth.bnauth`，**以明文 JSON 儲存，內含密鑰與還原資訊**。請妥善保管，不要公開或上傳資料檔。

新增、編輯名稱與備註、刪除、分組管理、匯入或還原等會修改資料檔的對話框，須先關閉才能關閉主程式。若先要求關閉主程式，關掉對話框後要再關閉一次。「說明」與「查看驗證器資料」可直接隨主程式關閉。未執行匯出作業時，匯出視窗也可直接隨主程式關閉。

每筆驗證器都需要有效的 40 位十六進位密鑰。0.4.0 可讀取符合格式的 0.3.0 主檔和備份。新版保存或匯出的檔案請用 0.4.0 開啟。要回到 0.3.0 時，請使用更新前留存的原始副本。

若設定檔唯讀或所在資料夾無法寫入，仍可查看、複製驗證碼及匯出。恢復寫入權限後，按「重新讀取」即可編輯。

手動保留副本時，先正常關閉程式並確認沒有保存或清理錯誤，再複製資料檔。若要用文字編輯器修改，也請先關閉程式並保留副本；修改後仍須符合資料格式與容量限制。

成功校時會把全部驗證器共用的來源、採樣時間、偏移及往返耗時保存於 `.bnauth`。重開後套用已保存偏移，時間持續隨目前本機時間推進，不停留在上次伺服器採樣時間。完整與分組備份也保留這筆共用紀錄；分組匯入不覆蓋目標的校時。

待保存的有效校時可和驗證器變更一起寫入。寫入失敗時可按「重試」。系統時間跳動時，BNAuth 會提示重新校時並沿用原偏移。

手動校時結果保存成功後，底部顯示「校時成功」。將滑鼠移到時鐘按鈕，可查看「上次校時」、往返耗時或「尚未校時」。

## 自行編譯

### 準備環境

- Windows x64。
- [Rust](https://www.rust-lang.org/tools/install) 1.95 或更新版本，使用 `x86_64-pc-windows-msvc` 工具鏈。
- [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，安裝「使用 C++ 的桌面開發」（Desktop development with C++）工作負載及 Windows SDK。
- Git；也可從 GitHub 的「Code → Download ZIP」取得原始碼。

### 編譯 EXE

安裝完成後，開啟一般命令提示字元（CMD）。若要更新既有成品，請先關閉正在執行的 `dist\BNAuth.exe`，再執行：

```bat
git clone https://github.com/EKE00372/BNAuth.git
cd BNAuth
build.cmd
```

若使用 ZIP 取得原始碼，先切換到解壓縮後包含 `Cargo.toml` 的資料夾，再執行最後一行。

首次編譯需要連線下載依賴。腳本會自動尋找 Rust 與 Visual Studio C++ 工具、設定 x64 編譯環境，再建立 Release 成品。完成後，執行檔位於 `dist\BNAuth.exe`；可將它複製到其他可寫入的本機 NTFS 資料夾使用。

Rust 會從 `PATH`、`CARGO_HOME\bin` 或使用者的 `.cargo\bin` 尋找；非標準安裝位置可透過 `BNAUTH_TOOLCHAIN` 指定包含 `cargo.exe`、`rustc.exe` 的目錄。Visual Studio 會使用目前的開發環境，或透過官方 `vswhere` 尋找已安裝的 C++ 工具，不綁定版本號與安裝位置。

依賴快取與中間編譯檔預設放在 `.build`，也支援既有的 `CARGO_HOME`、`CARGO_TARGET_DIR` 設定。只有不帶參數執行 `build.cmd` 時，才會將成品複製到 `dist`；帶參數時會執行對應的 Cargo 指令。

若依賴已快取，可離線編譯：

```bat
build.cmd build --release --locked --offline
```

這個指令只編譯，成品預設位於 `.build\target\release\BNAuth.exe`。也可在 Visual Studio 的 x64 開發命令提示字元直接執行 `cargo build --release --locked`，成品預設位於 `target\release\BNAuth.exe`。

### 執行測試

在專案根目錄中執行：

```bat
build.cmd test --workspace --all-targets --locked
```

`tests` 另附需手動執行的 Windows 回歸驗證腳本，修改相關功能時可使用：

- [native-links.ps1](tests/native-links.ps1)：確認原生開網址功能已包含在依賴中。
- [windows-first-visible.ps1](tests/windows-first-visible.ps1)：檢查 EXE 第一次顯示時的視窗位置與尺寸。
- [winauth2-compatibility.ps1](tests/winauth2-compatibility.ps1)：以公開測試密鑰核對 WinAuth2 原版讀寫組件、產碼及附加欄位；執行方式與參數見腳本開頭。

它們不會在一般編譯或 `cargo test` 時自動執行，驗證產物預設放在 `.build`。

## 發布 Release

發布由 GitHub Actions 的 **Build and Release** 手動啟動，一般提交、推送代碼或標籤都不會觸發。

1. 確認根目錄 `Cargo.toml` 的版本號正確，並將代碼與相應的 `Cargo.lock` 變更提交、推送。輸入的發布版本須與這份代碼的版本相同。
2. 在 GitHub 開啟 **Actions → Build and Release → Run workflow**，選擇要發布的分支，通常為 `main`。
3. 輸入與所選 commit 的 `Cargo.toml` 相同的版本號，例如 `0.4.0` 或 `v0.4.0`，再按 **Run workflow**。
4. 流程會核對版本，執行全部 workspace 測試、原生開網址依賴檢查，再編譯 Windows x64 Release EXE。全部成功後建立相應的版本標籤與 Release，上傳單一 `BNAuth.exe`；有對應的 `.github/release-notes/v<版本>.md` 時使用該版本說明，否則自動生成更新說明。

編譯與版本標籤固定使用本次執行選定的 commit。已存在的 Release 不會覆蓋；既有標籤若指向其他 commit，也會停止。版本含 `-beta.1`、`-rc.1` 等預發布後綴時，會標記為 Pre-release。

發布附件只包含本次編譯的 EXE，資料檔與工作產物不會上傳。流程使用 GitHub 自動提供的 `GITHUB_TOKEN`，不需另設個人存取權杖。
