# BNAuth

BNAuth 是 Windows 戰網驗證器管理工具，以 Rust 與 egui／eframe 開發。可在本機管理驗證器、產生八位驗證碼，並將資料保存於程式所在目錄。

目前版本為 **0.3.0，仍在開發中**。

本版新增 WinAuth2 XML 匯出、分組匯入與匯出、完整資料庫備份與還原，並保存全部驗證器共用的校時結果。更新內容見 [v0.3.0 版本說明](.github/release-notes/v0.3.0.md)。

## 功能

- 手動匯入40位十六進位密鑰，或74位 WinAuth2 明文 `secretdata`。
- 匯入前預覽驗證器資料與目前驗證碼，方便與其他驗證器比對。
- 產生每30秒更新的八位驗證碼，支援複製與離線產碼。
- 所有驗證器共用校時；成功結果保存於 `.bnauth`，重開後沿用。新密鑰匯入成功後會嘗試校時，也可手動校時。
- 分組、名稱搜尋、名稱與備註編輯、拖曳排序、批次移組及刪除。
- 單筆匯出 WinAuth2 XML，包含可產碼資料及標題、備註、序號、還原碼。
- 右鍵分頁匯出該分組全部驗證器，保存為「分組名.bnauth」。
- 匯入 `.bnauth` 分組檔，預覽後整批保存，保留分組名稱、完整資料與組內順序。
- 完整資料庫備份與還原，保留全部分組名稱、驗證器資料、分頁及組內排序；取代前自動保留目前資料庫副本。
- 以可直接閱讀、編輯的 JSON 資料檔自動保存，執行期間鎖住資料檔。
- 視窗置頂、拖動與調整大小；每次啟動使用固定尺寸及位置。

全庫最多1000筆驗證器、20個分組（含未分組），每組最多100筆。目前尚未提供密碼加密、完整備份合併、分組檔首次還原、XML 匯入，以及驗證器的線上建立、恢復或綁定。

## 下載

下載頁：[GitHub Releases](https://github.com/EKE00372/BNAuth/releases)。

選擇版本，在 **Assets** 下載 `BNAuth.exe`，即可直接執行，不需解壓縮或安裝。若尚無可下載的版本，請依下方步驟自行編譯。

EXE 已包含字型與授權文字；完整授權可在程式「說明」視窗的授權文字上按右鍵複製。

## 開始使用

1. 將 `BNAuth.exe` 放在本機 NTFS 磁碟中可寫入的資料夾，開啟程式。
2. 首次使用時按「建立資料」，建立空的 `BNAuth.bnauth` 資料檔；已有完整備份時，可按「從備份還原…」。
3. 按「新增」，填寫名稱、選擇分組，貼上40位密鑰或74位明文資料。備註、序號與還原碼可選填；74位資料會自動帶入序號。
4. 按「預覽匯入」，核對資料及八位驗證碼，再按「確認匯入並保存」。相同密鑰不會重複新增，只會經確認後補齊缺少的資料。
5. 在清單中按複製圖示取得驗證碼，按時鐘圖示校時。成功的共用校時會保存，重開後以「目前本機時間＋已保存偏移」繼續產碼；沒有有效可用的共用校時時使用本機時間，請保持電腦日期與時間正確。

### 匯出 WinAuth2 XML

1. 在驗證器右側按三點選單，選「匯出 WinAuth2 XML…」。
2. 閱讀匯出說明後按「另存 XML…」，選擇位置並保存。預設位置為 EXE 同目錄，預設檔名為「標題.xml」，存檔時可自行修改。同名檔案會先詢問是否取代。
3. 用 WinAuth2 開啟 XML。每個檔案包含一筆驗證器；沒有密鑰的紀錄無法匯出，缺少的序號與還原碼維持空白。

XML **以明文保存密鑰與還原資料**。標題、備註、序號與保存的還原碼另存於 `bnauth:metadata` 擴充區，包含完整文字與換行；WinAuth2 會忽略此區，仍可讀取密鑰與實際序號並產碼。**用 WinAuth2 重新保存後，擴充區會丟失，請保留 BNAuth 原匯出檔。** WinAuth2 畫面顯示的還原碼由它自行推算，可能與 XML 保存的值不同。

XML 會寫入和全部驗證器相同的共用校時偏移，重開後也沿用 `.bnauth` 保存的值。WinAuth2 會把零時差視為「尚未校時」，首次取碼時嘗試連線舊版校時服務；只有實際偏移為零或沒有有效可用的共用校時時，XML 才寫入 **1 毫秒的相容調整值**。沒有可用校時包含尚未成功校時或已偵測到系統時鐘跳動，此時請檢查 Windows 時間並手動校時。1 毫秒調整只供 WinAuth2 相容，不改寫資料庫保存的偏移，也不是服務校時結果。WinAuth2 的手動校時仍會使用它自己的舊版服務，該操作仍可能連線失敗。

相容驗證使用 WinAuth **2.0.8.185 對應官方原碼**重新編譯的讀寫組件。首輪已核對含序號／純密鑰 XML 的讀取、固定時間 RFC 6238 產碼、重新保存及再次讀取；首次取碼的自動連線另按零時差修正驗證，使用者持有的原始 EXE 仍須另行核對。

### 匯出分組

1. 在要匯出的分頁上按右鍵，選「匯出此分組…」。不需先切換到該分頁。
2. 核對分組名稱與驗證器總數，再按「另存分組檔…」。
3. 預設檔名為「分組名.bnauth」，存檔時可自行修改；預設放在 EXE 同目錄。同名檔案會先詢問是否取代，正在使用的 `BNAuth.bnauth` 主檔不能被匯出覆蓋。

分組檔包含該組全部已保存的驗證器，保留標題、備註、密鑰、序號、還原碼、完整歷史欄位及組內順序，包含尚未取得密鑰的紀錄。搜尋條件與目前選取不影響匯出範圍；空分組與「未分組」也可匯出。

檔案是**明文 UTF-8 JSON**，使用 `scope=group`，只包含選定分組。請使用下方的分組匯入入口；它不能直接當作完整的 `BNAuth.bnauth` 主檔開啟。

### 匯入分組

1. 先建立或開啟目前資料庫，在任一分頁上按右鍵，選「匯入分組檔…」。
2. 按「選擇分組檔…」，選取先前匯出的 `.bnauth` 分組檔。
3. 核對來源分組、總筆數、來源順序及每筆處理方式，再按「確認匯入並保存」。成功後切換到匯入的分組；保存失敗可按「重試保存」。

沒有同名分組時，以來源原名建立分組，保留驗證器的標題、備註、密鑰、序號、還原碼及歷史欄位，包含沒有密鑰的紀錄。已有同名分組時，保留該組其他項目的相對順序，再將來源項目按檔案順序放在末尾。「未分組」匯入既有的系統未分組。

相同密鑰不會新增副本；同一筆原生紀錄可補齊缺少的資料。已存在其他分組的重複項目會在確認後移入來源分組，預覽會列明。標題、備註、序號或還原碼有衝突，以及匯入後超過容量時，整批停止匯入，請先核對資料。完全相同且順序未變的再次匯入不保存；取消或失敗不改寫來源檔。

### 備份完整資料庫

1. 在任一分頁上按右鍵，選「備份完整資料庫…」。
2. 核對全部分組與驗證器總數，再按「另存完整備份…」。
3. 預設檔名為 `BNAuth-full.bnauth`，存檔時可自行修改；預設放在 EXE 同目錄。同名檔案先詢問是否取代，正在使用的主檔不能被備份覆蓋。

完整備份保留所有分組名稱、分頁順序、組內排序，以及全部驗證器欄位與歷史資料，包含空分組、未分組及沒有密鑰的紀錄。搜尋條件與目前選取不影響範圍。檔案為**明文 UTF-8 JSON**，使用 `scope=full`，請妥善保管。

### 還原完整資料庫

1. 在任一分頁上按右鍵，選「還原完整資料庫…」。同目錄尚無資料庫時，直接按啟動畫面的「從備份還原…」。
2. 選取完整 `.bnauth` 備份，核對來源的全部分組、排列順序與驗證器筆數。
3. 已有資料庫時，先核對目前資料與取代說明，勾選確認取代，再按「確認還原並保存」。沒有資料庫時，直接確認並建立主檔。

還原會以完整備份取代目前全部資料，保留來源的所有分組名稱、驗證器完整欄位、分頁與組內排序。來源檔案保持原樣；分組檔請使用「匯入分組檔…」。

取代前會在 EXE 同目錄建立並讀回驗證目前資料庫的獨立副本，檔名為 `BNAuth-before-restore-<timestamp>-<UUID>.bnauth`，timestamp 為 Unix 毫秒時間。副本建立或驗證失敗時停止還原；副本會保留，可再從完整還原入口選取。保存失敗可按「重試保存」，成功後才更新畫面。完整還原會載入備份保存的共用校時偏移，以目前本機時間加上該偏移繼續產碼；分組匯入則保留目前資料庫的共用校時。

同一次執行中已判定失效的校時樣本，會在確認完整還原時從候選的共用校時清除，一次保存完成，來源檔與來源歷史保留原值。不同的有效樣本照常沿用；還原送出後才發現失效時，仍會另行保存清除。來源追溯紀錄最多1000筆，完整還原須再新增一筆；來源已滿1000筆時會停止還原，保留全部歷史，這項限制本輪不調整。

### 資料保存

資料自動保存於 EXE 同目錄的 `BNAuth.bnauth`，**以明文 JSON 儲存，內含密鑰與還原資訊**。請妥善保管，不要公開或上傳資料檔。

手動保留副本時，先正常關閉程式並確認沒有保存或清理錯誤，再複製資料檔。若要用文字編輯器修改，也請先關閉程式並保留副本；修改後仍須符合資料格式與容量限制。

成功校時會把全部驗證器共用的來源、採樣時間、偏移及往返耗時保存於 `.bnauth`。重開後套用已保存偏移，時間持續隨目前本機時間推進，不停留在上次伺服器採樣時間。完整與分組備份也保留這筆共用紀錄；分組匯入不覆蓋目標的校時。

校時結果沿用一般保存流程；寫入失敗時可按「重試保存」。若同時正在保存驗證器或整理資料，會等該次變更完成，再把校時結果加入最新資料，保留使用者的修改。

偵測系統跳鐘而使校時失效時，會停止使用該偏移，並保存清除後的共用校時紀錄；清除成功後，重開也不會再次套用這份失效偏移。清除保存失敗時可重試。新有效樣本仍可立即供本次產碼使用，保存成功後才成為重新讀取時可沿用的結果。同一次執行中，已判定失效的舊紀錄會持續停用；新樣本保存失敗、被放棄、完成保存，或之後從舊備份還原，都不會讓該舊紀錄重新生效。

只有手動按時鐘按鈕，才會在底部顯示校時進度與結果；匯入後自動校時及載入已保存結果保持安靜。將滑鼠移到時鐘按鈕，可查看目前校時狀態與最後錯誤；載入保存結果沿用「已校時」狀態，不另加載入說明。實際保存失敗仍會停留在保存處理畫面，供重試或處理。

明確重新讀取資料庫時，會取消前一次開庫的未完成校時及待存校時；即使重新讀取失敗，也可正常關閉，已在進行的資料保存與清理仍依畫面提示處理。Windows 匯出會固定選定時的實際資料夾，鎖住自己建立的暫存檔，完成寫入、刷盤、安裝及讀回核對；匯出期間資料夾別名被改指向其他位置，也不會轉而寫入該位置。完成提示會顯示檔案實際保存的位置，請依該位置尋找檔案。目標檔被其他程式鎖住時，匯出失敗並保留原檔。

## 自行編譯

### 準備環境

- Windows x64。
- [Rust](https://www.rust-lang.org/tools/install) 1.95 或更新版本，使用 `x86_64-pc-windows-msvc` 工具鏈。
- [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，安裝「使用 C++ 的桌面開發」（Desktop development with C++）工作負載及 Windows SDK。
- Git；也可從 GitHub 的「Code → Download ZIP」取得原始碼。

### 編譯 EXE

安裝完成後，開啟一般命令提示字元（CMD）。若要更新既有成品，請先關閉正在執行的 `dist\BNAuth.exe`，再執行：

```bat
git clone https://github.com/EKE00372/BNAuth.git
cd BNAuth
build.cmd
```

若使用 ZIP 取得原始碼，先切換到解壓縮後包含 `Cargo.toml` 的資料夾，再執行最後一行。

首次編譯需要連線下載依賴。腳本會自動尋找 Rust 與 Visual Studio C++ 工具、設定 x64 編譯環境，再建立 Release 成品。完成後，執行檔位於 `dist\BNAuth.exe`；可將它複製到其他可寫入的本機 NTFS 資料夾使用。

若使用 PowerShell，請將指令寫成 `.\build.cmd`。

Rust 會從 `PATH`、`CARGO_HOME\bin` 或使用者的 `.cargo\bin` 尋找；非標準安裝位置可透過 `BNAUTH_TOOLCHAIN` 指定包含 `cargo.exe`、`rustc.exe` 的目錄。Visual Studio 會使用目前的開發環境，或透過官方 `vswhere` 尋找已安裝的 C++ 工具，不綁定版本號與安裝位置。

依賴快取與中間編譯檔預設放在 `.build`，也支援既有的 `CARGO_HOME`、`CARGO_TARGET_DIR` 設定。只有不帶參數執行 `build.cmd` 時，才會將成品複製到 `dist`；帶參數時會執行對應的 Cargo 指令。

若依賴已快取，可離線編譯：

```bat
build.cmd build --release --locked --offline
```

這個指令只編譯，成品預設位於 `.build\target\release\BNAuth.exe`。也可在 Visual Studio 的 x64 開發命令提示字元直接執行 `cargo build --release --locked`，成品預設位於 `target\release\BNAuth.exe`。

### 執行測試

在專案根目錄中執行：

```bat
build.cmd test --workspace --all-targets --locked
```

`tests` 另附需手動執行的 Windows 回歸驗證腳本，修改相關功能時可使用：

- [native-links.ps1](tests/native-links.ps1)：確認原生開網址功能已包含在依賴中。
- [windows-first-visible.ps1](tests/windows-first-visible.ps1)：檢查 EXE 第一次顯示時的視窗位置與尺寸。
- [winauth2-compatibility.ps1](tests/winauth2-compatibility.ps1)：以公開測試密鑰核對 WinAuth2 原版讀寫組件、產碼及附加欄位；執行方式與參數見腳本開頭。

它們不會在一般編譯或 `cargo test` 時自動執行，驗證產物預設放在 `.build`。

## 發布 Release

發布由 GitHub Actions 的 **Build and Release** 手動啟動，一般提交、推送代碼或標籤都不會觸發。

1. 確認根目錄 `Cargo.toml` 的版本號正確，並將代碼與相應的 `Cargo.lock` 變更提交、推送。輸入的發布版本須與這份代碼的版本相同。
2. 在 GitHub 開啟 **Actions → Build and Release → Run workflow**，選擇要發布的分支，通常為 `main`。
3. 輸入版本號，例如 `0.3.0` 或 `v0.3.0`，再按 **Run workflow**。
4. 流程會核對版本，執行全部 workspace 測試、原生開網址依賴檢查，再編譯 Windows x64 Release EXE。全部成功後建立 `v0.3.0` 這類版本標籤與 Release，上傳單一 `BNAuth.exe`；有對應的 `.github/release-notes/v<版本>.md` 時使用該版本說明，否則自動生成更新說明。

編譯與版本標籤固定使用本次執行選定的 commit。已存在的 Release 不會覆蓋；既有標籤若指向其他 commit，也會停止。版本含 `-beta.1`、`-rc.1` 等預發布後綴時，會標記為 Pre-release。

發布附件只包含本次編譯的 EXE，資料檔與工作產物不會上傳。流程使用 GitHub 自動提供的 `GITHUB_TOKEN`，不需另設個人存取權杖。
